# UI rules (src/)

- The chat composer uses AI Elements PromptInput primitives; its existing file-routing callbacks remain separate from the primitive's attachment collection. Why: preserves ZIP/conversion behavior while sharing accessible input and submission controls.
- Speech text is joined through the browser-safe appendTranscript helper, with regression tests. Why: preserves typed text and whitespace across recognition updates without coupling transcription to a service.
- Drawer uses AppDrawerView in the persistent NavigationGestures overlay; protected /drawer stays a direct entry. Search is inline. Why: preserves mounted pages and streams with one drawer/search UI.
- Incognito uses a dedicated route and workspace-only React state, bypassing history writes, background jobs, and persistent AI generators. Why: temporary messages and attachments must never reach browser storage; replies come from the stateless /api/chat route.
- Picture/video creation pages are retired: /images and /videos (and their chat URLs) are thin legacy redirects to /chat. Why: Vision is a text-output system; media is only format-converted, never generated or edited.
- Deep Thinking and job progress render compact text statuses; terminal failures expand recorded details with frozen elapsed time, and completed downloads remain visible. Why: no large progress cards and failures remain inspectable after reopening.
- Sidebar feature links share SidebarFeatures, secondary collection pages share WorkspaceShell, and Library reuses Search filtered to assets. Why: keeps navigation and stored-item discovery consistent.
- Projects use user-scoped workspace_projects through the existing local backend adapter, with creation in a separate view and shared icon definitions. Why: preserves browser-local persistence and consistent icons across creation and listing.
- Library derives applicable file-type filters from the shared search index metadata. Why: avoids separate storage and keeps Search and Library classifications consistent.
- The chat screen is mounted once by the `/chat` layout route (`src/routes/chat.tsx`); `/chat/`, `/chat/$chatId` and `/chat/incognito` render nothing and only set address/title, reading the chat id from the pathname. Why: separate leaf routes remounted the screen on a new chat address, looking like a reload and dropping the live reply.
- Route errors use the shared `components/route-error` as the router default, and failed page-file downloads retry in place (3 tries) before the published-only single reload. Why: keeps the open screen intact instead of full-page reloads.
- Chat mode is per conversation, owned by ChatWorkspace and saved through `lib/chat-mode-store` (a pre-send draft is adopted by the new chat; incognito stays in memory). Why: a mode must stay on across replies, navigation and reloads until the user turns it off.
- Swipe routing is decided by `gestureSurface`/`swipeAction` in `lib/navigation-motion` (Chat ↔ drawer/Projects, drawer pages → drawer), and drawer pages open with `__visionDirection: "left"`. Pull-down (top→down) on Chat or the App Drawer opens Search via `requestSearch`/`DRAWER_SEARCH_EVENT`, reusing the drawer's animated morph. Why: one tested rule set for gestures and their matching transition direction.

- Chat replies share one Markdown renderer; each content purpose has its own block component in `components/chat/<purpose>/` (`code` for programming/literal text, `markdown` for rendered prose, `table` for tables) sharing `full-screen-code-view`, `zoom-controls` and the content-block styles; Markdown keeps rendered content and clean rich copying, text stays literal, and programming fences keep syntax highlighting. Format labels remain visible at every size. Why: one UI prevents copy-block styles diverging while preserving each content type.
- Chat Markdown tables use `components/chat/table` with original-source copying, stable view-only sorting and formula-safe CSV exports from `lib/table-export`. Why: multiple tables remain independent and spreadsheet downloads cannot execute cell formulas.
- Code blocks/previews share the accessible full-screen numbered viewer and sandboxed preview; media queries hide desktop tools on mobile; frames never get same-origin privileges. Why: shared capabilities without generated-code access to the app.
- Shared content-block frames cap height to natural content via inline container units (ResizeObserver only detects clipping), take border and toolbar from theme colours with code-canvas tokens optional, and keep the shadow on the code canvas only. Why: short replies stay compact, and blocks without a code canvas never fall back to the text colour's bright outline.
- NavigationGestures preserves Outlet and shares panel motion for App Drawer and Projects (taps: Web Animations; swipes: finger 1:1 then spring); the App Drawer is pre-built while idle and kept hidden off-screen (reset via resetKey on close), so a swipe never waits for mounting. Drawer children animate only during inline Search morphs. Why: instant, bounce-free tracking while preserving streams.
- UI hides routing events via task state and `lib/status-visibility.ts`, retaining the previous operation. Why: separates diagnostics from progress.
- Saved file replies restore from owner-scoped jobs; questions/session writes commit before dispatch, job-recovery merges by task id and reconnects after network errors, and download controls wrap on small screens. Why: accepted work and downloads must not disappear after navigation or a temporary failed read.
- Replies with task activity use only the workspace's bounded reveal schedule, not the legacy character typewriter. Why: completed long answers must not remain hidden behind a second animation.
- Reply footers use AI Elements actions; branches copy the selected prefix with fresh message ids and file snapshots, deletions persist metadata tombstones, and reports use owner-scoped support tickets. Why: actions survive reload without resuming deleted jobs or changing the original chat.
- Workspace pages share fade/grid controls; Settings uses Radix switches/radios. Drafts pass URL context to addChat; ProjectChatHeader uses ProjectMenu; lists sort by creation with pins first. Why: consistent UI and isolated chats.
