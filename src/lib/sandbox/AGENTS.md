- Long Context Generation stores everything in the separate "vision-sandbox" D1 (binding SANDBOX_DB via `db.server.ts`, REST fallback off-Worker); the main "vision" D1 is never touched. `generation.ts` is pure (plan, waves, context layers, checksum, validation); `store.server.ts` owns owner-scoped SQL with CAS transitions and idempotent inserts; `runner.server.ts` runs plan → parallel waves → assemble → validate via `orchestrateText`, resumable from persisted state. Why: temporary output generation is isolated from production data and every step survives crashes without duplicating work.
- Runners persist unexpected failures and settle parallel work before termination; assembly checks the full plan and saved checksums, and in-run retries reset only their own failed chunk. Why: recovery cannot steal active work or silently deliver missing sections.
